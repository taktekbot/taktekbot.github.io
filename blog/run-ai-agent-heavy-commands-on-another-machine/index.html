Run your AI agent's heavy commands on another machine

4 Nov 2026

Decide what the small machine is for, and let a hook enforce it. A rule in the instructions alone gets forgotten.

A coding agent runs commands where it lives. If it lives on a small laptop, that's where npm install, the test suite, the Docker build and the headless browser run too. The laptop gets slow, and so does everything else on it, including the agent.

The laptop I mean has 8 GB of memory. Its job is narrow: keep a logged-in browser open, and hold a few things that only exist there. A Linux machine with 30 GB of memory sat on the same network with little to do. On 13 October the laptop's swap reached 19 of 20 GB. The rule we wrote that day was simple: anything that doesn't need the laptop runs on the other machine. The rule went into the instructions every agent reads. A week later I made a hook enforce it.

On 20 October I added a hook that refuses heavy commands on the laptop and prints the ssh command to use instead. In the 11 days to 31 October it refused 6 commands across 5 agent sessions: 3 Go builds or test runs, 1 package install, 1 make and 1 container command. In 3 other cases an agent marked a command as needing the laptop and ran it there. Those are small numbers. I don't know how many heavy commands the agents would have run without the reminder that now opens each session, so I can't tell you how much of the quiet is the rule working.

Why a written rule isn't enough

Instructions compete with the task. An agent fixing a failing test reaches for the test runner, in the directory it's in, because that's the fastest way to see the result. "Run heavy things elsewhere" is one line among hundreds in its context. A hook is different: it runs before every shell command, and it can say no.

How a PreToolUse hook works

Claude Code calls a PreToolUse hook before it runs a tool. The hook gets the planned call as JSON on standard input. For a shell command, the command is in tool_input.command. If the hook exits with code 2, the command doesn't run, and whatever the hook printed to standard error goes back to the agent as the reason. The agent reads it and tries again, usually the way the message says.

So the message matters as much as the check. "Blocked" makes an agent guess. A message with the exact command to run, where, and what to do first gets followed.

A minimal hook

This is a short version in Python, standard library only. It splits the command line into simple commands, ignores anything in quotes (an argument, not a command), lets through anything already going over ssh, scp or rsync, and refuses the rest if it matches a heavy pattern:

#!/usr/bin/env python3
"""Claude Code PreToolUse hook: refuse heavy shell commands here, and say how to run them on BIG_HOST."""
import json, os, re, sys

HOST = os.environ.get("BIG_HOST", "bigbox")
HEAVY = [
    r"^(npm|pnpm|yarn) (install|ci|i)\b", r"^pip3? install\b",
    r"^(npm|pnpm|yarn) (run )?(build|test)\b", r"^go (build|test)\b", r"^cargo (build|test)\b",
    r"^make\b", r"^docker (build|compose)\b", r"^pytest\b",
    r"^ffmpeg\b", r"^npx (playwright|lighthouse)\b",
]

try:
    command = json.load(sys.stdin)["tool_input"]["command"]
except (ValueError, KeyError, TypeError):
    sys.exit(0)  # never block on our own error

# Quoted text is an argument, not a command: blank it out before splitting the line.
bare = re.sub(r"'[^']*'|\"[^\"]*\"", "''", command)
for part in re.split(r"&&|\|\||;|\|", bare):
    part = part.strip()
    if re.match(r"^(ssh|scp|rsync)\b", part) or part.startswith("RUN_HERE=1 "):
        continue  # already remote, or marked as needing this machine
    if any(re.match(p, part) for p in HEAVY):
        print(f"`{part}` is heavy. Run it on {HOST} instead:\n"
              f"  ssh {HOST} 'cd ~/src/<repo> && git pull --ff-only && {part}'\n"
              "Commit and push first so the other machine has your changes. "
              "If it truly needs this machine, prefix it with RUN_HERE=1 and say why.", file=sys.stderr)
        sys.exit(2)

Save it as ~/.claude/hooks/send_heavy_elsewhere.py and register it in ~/.claude/settings.json:

{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "python3 ~/.claude/hooks/send_heavy_elsewhere.py", "timeout": 10 }] }
    ]
  }
}

Test it before you trust it. Pipe a fake call in and check the exit code:

echo '{"tool_input":{"command":"npm install"}}' | python3 ~/.claude/hooks/send_heavy_elsewhere.py; echo $?
# prints the ssh suggestion, then 2
echo '{"tool_input":{"command":"ssh bigbox '\''cd app && npm install'\''"}}' | python3 ~/.claude/hooks/send_heavy_elsewhere.py; echo $?
# prints nothing, then 0

What I learned getting it right

  • Strip quoted text first. My first version split the line on && before anything else, so ssh bigbox 'cd app && npm install' came apart into npm install' and got refused. That is exactly the command you want to allow. Blank out quoted strings before you split.
  • Never block on your own error. If the input isn't what you expect, exit 0. A hook that crashes into a refusal stops all work, and the agent can't tell why.
  • Give the agent a way out, and make it explain. Some commands really do need the small machine: signing an app with a key that lives there, or a browser that's logged in. A prefix like RUN_HERE=1 lets the command through, and asking for a one-line reason keeps it rare. 3 times in 11 days, in my case.
  • Say "commit and push first". The other machine runs whatever its copy of the repository holds. An agent that runs the tests remotely before pushing its edit tests the old code, passes, and moves on.
  • Long jobs need to outlive the ssh session. For anything over a few minutes, tell the agent to start it with systemd-run --user or inside tmux on the other machine and check back, so a dropped connection doesn't kill the build.

Set up the other machine once

  1. Give the laptop an ssh key the other machine accepts, and a short host name in ~/.ssh/config, so ssh bigbox works with no prompt.
  2. Clone the repositories there, in one folder, with the same names as on the laptop.
  3. Install the same toolchains: the same Node, Go or Python versions the projects expect.
  4. Run one heavy command by hand over ssh. If it needs a password or asks a question, the agent will get stuck at the same place.

If you want it done for you

The hook I run is offload, open source under MIT, Python standard library only. It knows more heavy commands than the short version above (headless browsers, Lighthouse, OCR, video encoding, bulk model runs), reads its host and rules from one JSON file, warns when swap is high, and adds a one-line reminder at the start of every session.

git clone https://github.com/taktekhq/offload.git ~/offload
~/offload/offload check npm install    # see what it would say
