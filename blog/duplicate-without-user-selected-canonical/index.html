"Duplicate without user-selected canonical" in Search Console: what it means and how to fix it

25 Oct 2026

Your page has a twin, and you never said which one is the real one. So Google picked.

"Duplicate without user-selected canonical" means Google found two or more addresses that show the same page, and none of them says which address is the main one. So Google chose one itself and left the others out of search results. The excluded address isn't broken, and nothing is penalised. You just didn't get a say in which copy people see.

The most common twin I've seen is the home page itself. On 16 October I checked 191 small business websites from a business directory, and 48 of them answered on both https://example.com/ and https://www.example.com/ without sending one to the other. On 18 October I fetched both copies of those home pages and looked for a canonical tag, the one line that names the main copy. In the morning run, 36 of the 48 had no canonical on either copy, and 1 named a different address on each. A re-run that evening, with 47 of the sites answering, gave the same picture: 35 with none, 1 contradicting itself, 10 naming the same address from both copies. So roughly three in four of those sites leave Google to guess.

Below is what the status means, how to find your own twins, and the two fixes, in the order to do them.

The words, translated

  • Duplicate: two addresses that serve the same, or nearly the same, page. To Google, example.com/, www.example.com/, example.com/?ref=menu and example.com/index.html are four different addresses, even if you think of them as one page.
  • Canonical: the address you want shown in search results. Google indexes one copy of each page and folds the others into it.
  • User-selected: you told Google which one, with a redirect or a rel="canonical" tag. "Without user-selected" means you didn't, so the choice was Google's.

It has three neighbours in the same report. "Alternate page with proper canonical tag" means you did name a main copy and Google agreed: usually fine. "Duplicate, Google chose different canonical than user" means you named one and Google disagreed. The one in this guide comes before both: nobody named anything.

Is it a problem?

Often not much. If Google picked the address you would have picked, the right page shows in results and the twin just sits in this list.

It becomes a problem in three cases:

  • Google picked the wrong copy. For example the http:// one, or a version with a tracking parameter, or the address you're about to retire.
  • Links are split. Some people link to www, some to the bare address. Google says it consolidates signals for duplicates, but only once it has worked out they're duplicates, and the copy it keeps may not be the one your ads, business profile and printed cards point to.
  • The list is long. Hundreds of entries usually mean a pattern (a filter, a sort order, a session parameter in the address) that makes your site look many times bigger than it is, and Google spends visits on copies instead of new pages.

Check which copy Google picked

  1. In Search Console, open Indexing → Pages, scroll to "Why pages aren't indexed" and click Duplicate without user-selected canonical.
  2. Click one address in the list, then Inspect URL.
  3. Open Page indexing. Read two lines: User-declared canonical will say "None", and Google-selected canonical shows the copy Google kept.
  4. If the Google-selected address is the one you want, you can leave it. If not, keep going.

Check your own site for the home page twin

This is the check I ran on the 48 sites, for one site. Open Terminal on a Mac (on Windows, open PowerShell and type curl.exe instead of curl) and run these two lines with your own domain:

curl -sL -o /dev/null -w "%{http_code} %{url_effective}\n" https://example.com/
curl -sL -o /dev/null -w "%{http_code} %{url_effective}\n" https://www.example.com/

On Windows, replace /dev/null with NUL. Each line prints the status and the address you ended up on after any redirects.

  • Both lines end on the same address: one redirects to the other. Good, the home page has no twin.
  • Each line ends on its own address, both 200: you have the twin. This was 48 of 180 sites that answered on both.
  • One line fails: that's a different problem, covered in my website works without www but not with it.

Then look for a canonical tag on both copies:

curl -sL https://example.com/ | tr "\n" " " | grep -oi '<link[^>]*canonical[^>]*>'
curl -sL https://www.example.com/ | tr "\n" " " | grep -oi '<link[^>]*canonical[^>]*>'

The tr part joins the page into one line first, because some sites split the tag across lines and a plain grep misses it. No output means no canonical tag. If both lines print the same address, you're covered. If they print different addresses, each copy claims to be the real one, which is worse than saying nothing; one of my 48 did that.

Fix 1: redirect the twin

A redirect is the strongest signal. Google's own guide on duplicate URLs ranks it first: "Redirects: A strong signal that the target of the redirect should become canonical." It also fixes it for people, not only for Google: anyone who types the other address lands on the right one.

  • Cloudflare: Rules → Redirect Rules, create a rule for requests to the twin host, a dynamic redirect to the main host with the same path, status 301, and tick "Preserve query string".
  • WordPress: make sure both WordPress Address and Site Address under Settings → General use the host you want. WordPress then redirects the other host to it, as long as the server sends the other host to the same WordPress at all.
  • Hosted builders (Wix, Squarespace, Shopify): in the domains screen, set one domain as primary. The others redirect to it.
  • Apache or nginx: a 301 from the twin host to the main one, keeping the path. If you have both a www rule and an http-to-https rule, test that they don't chain into two hops.

Pick one host and use it everywhere: in the redirect, in your sitemap, in your internal links and in your canonical tags. Which one doesn't matter to Google. Mixing them does.

Fix 2: a canonical tag on every page

Redirects can't handle twins that have to stay reachable, like a page with ?utm_source= on the end, or a product reachable from two categories. For those, put this in the <head> of each page, naming that page's main address:

<link rel="canonical" href="https://www.example.com/services/">

Three rules from Google's guide that I see broken most:

  • Use the full address, with https:// and the host. Google supports short relative paths but recommends absolute ones.
  • Don't use robots.txt or noindex to hide twins. Google lists both as wrong tools for this: a blocked page can still be indexed, and a noindex page drops out instead of passing its signals on.
  • Each page names itself, not the home page. A whole site whose canonical says "home page" tells Google every page is a copy of it.

On WordPress, Yoast SEO, Rank Math and All in One SEO all print a self-naming canonical on every page by default. If you have one installed and the check above still printed nothing, a cache or a theme may be stripping the head; clear the cache and check again.

After the fix

  1. Run both checks again and make sure the twin now redirects and the main copy prints its own canonical.
  2. In Search Console, inspect the main address and click Request indexing.
  3. Click Validate fix on the status only if every address in its list is a twin you've dealt with. If the list also holds filter or tracking addresses you're keeping, skip validation: one leftover stops it.
  4. Give it time. The twins leave this list as Google revisits them, which can take weeks for pages it rarely crawls. Moving into "Page with redirect" or "Alternate page with proper canonical tag" is the good outcome: it means Google now knows which one you meant.

Sources: Google Search Central, How to specify a canonical URL with rel="canonical" and other methods, read on 18 October 2026.
