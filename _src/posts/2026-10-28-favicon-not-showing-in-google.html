A favicon is the small square icon next to your site's name in Google's results, and in the browser tab. When Google can't use yours, it shows a plain grey globe instead. Google's favicon help lists what it needs: a <link> tag on your home page pointing to the icon, an image that is square ("1:1 aspect ratio") and "at least 8x8px", in one of these file types: "BMP, GIF, ICO, PNG, JPEG, PPM, and TIFF". Googlebot must be allowed to fetch the home page and the icon. Even then, "A favicon isn't guaranteed to appear".

On 24 October I checked those rules on 187 small business websites from a business directory. 182 home pages answered. I read every icon link in each page's <head>, downloaded every icon file, and measured it. 16 sites had no icon link at all. Of the 166 that had one, 39 had no icon that passes Google's written rules. The most common reason, on 15 sites, was an image that isn't square: some were a whole wide logo, like 3087 by 1185 pixels, and some were off by a few pixels, like 102 by 101. 8 sites offered only WebP files and 8 only SVG files, and neither format is on Google's list. 5 linked to an icon file that answered "404 not found". 3 put the image inside the tag itself instead of linking to a file.

That's 55 of 182 sites, almost a third, that give Google nothing it says it can use. I read the rules and the files; I didn't search for each site to see what Google actually shows, so take these as "fails the written rules", not "proven missing". Below is how to check your own site in the same four steps, and how to fix each problem.

The rules, in plain words

  1. A link tag on the home page. Somewhere between <head> and </head>: <link rel="icon" href="/favicon.png">. Google also reads rel="shortcut icon", rel="apple-touch-icon" and rel="apple-touch-icon-precomposed". It reads the home page only: "Google Search only supports one favicon per site", where a site is one hostname. A shop at shop.example.com can have its own; example.com/shop can't.
  2. A square image. Same width and height. Google's minimum is 8 by 8 pixels, and it recommends "larger than 48x48px". 34 of the 127 passing sites had nothing bigger than 48. They pass, but they're the ones that look blurry on a phone.
  3. A file type on the list. BMP, GIF, ICO, PNG, JPEG, PPM or TIFF. SVG and WebP aren't on it. A browser tab shows them fine, which is why nobody notices.
  4. A file Google can fetch. It has to answer with the image, not a 404, and robots.txt must not block it. The address should also stay the same: "The favicon URL must be stable".

Most sites set the favicon once, in their builder, and never look at it again. All four rules break silently: the browser tab still shows something, so the owner thinks it works.

Step 1: find the icon links on your home page

On a Mac or Linux, in Terminal (replace the address with yours):

curl -sL https://yoursite.com/ | tr "\n" " " | grep -io '<link[^>]*icon[^>]*>'

The tr part joins the page into one line first, because some builders split a tag over several lines and grep would miss it. On Windows, in PowerShell (I couldn't run this one; I have no PowerShell here):

(curl.exe -sL https://yoursite.com/) -join " " | Select-String -AllMatches '<link[^>]*icon[^>]*>' | % { $_.Matches.Value }

No terminal: open your home page in Chrome, press Ctrl+U (Cmd+Option+U on a Mac) to see the source, then Ctrl+F and search for icon.

Here's what this site printed:

<link rel="icon" href="/assets/favicon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/assets/apple-touch.png">

The first one is an SVG, which isn't on Google's list. The second is a PNG. So this site passes because of the second line, not the first. If yours prints nothing, you've found your problem: go to the fixes below.

A link that starts with href="data:image is the 3-site case: the picture is written into the page as text, with no file behind it. Google's help only talks about a URL to a file, so don't rely on it. Link a real file too.

Step 2: open each icon file

Take each href, put your domain in front if it starts with /, and open it in a new browser tab. You should see the image. A "page not found" here is the 5-site case: the page links to an icon that was deleted or moved, often after a theme change.

To check the answer code from a terminal (-L follows redirects, so you see where it ends):

curl -sL -o /dev/null -w "%{http_code} %{content_type}\n" https://yoursite.com/assets/apple-touch.png

On Windows, use curl.exe and -o NUL instead of -o /dev/null. You want 200 and a type that starts with image/. A 200 text/html means the server sent a web page, often a "not found" page that forgot to say 404.

Step 3: measure it and read its type

Download the file and ask for its size and type. On a Mac:

curl -sL -o icon.png https://yoursite.com/assets/apple-touch.png
file icon.png

For this site that prints PNG image data, 180 x 180. Square, PNG, larger than 48: it passes. On Windows, save the file, right-click it, choose Properties, then the Details tab, which lists the width and height. Don't trust the file name: file reads the real type, and a file called favicon.png can be a WebP inside.

An .ico file can hold several sizes. file lists how many icons it holds; the others are inside the same file, and any one square size of 8 or more is enough.

Step 4: make sure Google may fetch it

Open yoursite.com/robots.txt and look for a Disallow line that covers the folder your icon is in, under User-agent: *, Googlebot or Googlebot-Image. You can paste the file into my free robots.txt tester to see which bots it blocks. On 25 October I ran that check on the same 182 sites. I read each robots.txt the way Google does (the Googlebot-Image group first, then Googlebot, then *, longest rule wins) and tested every icon address in their links. None of the 182 blocked a favicon. 137 had only a * group, and 1 had a Googlebot-Image group. So robots.txt is rarely the cause, but check it last.

One site's robots.txt answered with a server error (500), on two tries a few seconds apart. That matters more than a Disallow line. Google's robots.txt guide says that for a 5xx, "For the first 12 hours, Google stops crawling the site", then it uses the last good copy for up to 30 days. Run curl -sL -o /dev/null -w "%{http_code}\n" https://yoursite.com/robots.txt. A 200 or a 404 is fine. A 5xx needs fixing first.

How to fix each problem

  • Not square. Don't upload your whole logo. Make a square version: the symbol or first letter alone, centred, with some empty space around it. 512 by 512 pixels PNG is a safe size for every place it's used. Shrinking a wide logo into a square makes it unreadable at 16 pixels anyway.
  • Off by a few pixels (102 by 101, 32 by 28). Open it in any image editor and set the canvas to the larger of the two sides. Nobody sees the extra pixel; Google's rule does.
  • SVG or WebP only. Keep it, and add a PNG beside it with a second link tag: <link rel="icon" href="/favicon.png" sizes="512x512">. Browsers pick what they support. Google picks from its list.
  • File missing. Upload the icon again and check the address in step 2 answers 200. If your builder moved it, the link changes too, so re-run step 1.
  • No link at all. 4 of the 16 sites with no link did have a file at /favicon.ico. Browsers look there by habit. Google's help only describes the link tag, so add one.

Where to set it if you don't edit HTML:

  • WordPress: Appearance, Customize, Site Identity, "Site Icon". WordPress asks for at least 512 by 512 and crops it square for you. It writes the link tags itself.

On Shopify, Wix, Squarespace and the rest, the setting is usually called "favicon" or "browser icon"; search the builder's help for that word. Whatever it accepts, upload a square PNG and run steps 1 to 3 on the live site afterwards, because some builders resize or convert the file.

After the fix: how long it takes

Google reads the favicon when it next crawls your home page. Its help: "crawling can take anywhere from several days to several weeks". To speed that up, open Search Console, paste your home page address into the URL Inspection box at the top, and click "Request indexing". When I requested indexing for six new pages on this site on 8 October, all six had been crawled within 4 minutes. That was the page, not a favicon, so I can't promise the icon updates that fast. It can't start before the crawl, though.

If the rules pass, weeks have gone by and it's still the grey globe, look at the image itself. Google says it replaces any favicon "it deems inappropriate" with a default icon, and wants one that is "visually representative of your website's brand". A blank square or a stock icon may be the reason. Google also has a favicon feedback form, linked at the bottom of its help page.
