"Blocked due to other 4xx issue" is a Search Console status. In plain words: Google asked your server for a page, and the server answered with an error code in the 400s that isn't one of the three with their own rows (401, 403 and 404). Google's HTTP status page says all 4xx errors except 429 are treated the same: the page isn't indexed, and if it was indexed, it's removed.

On 5 November I asked 101 of the most visited domains (the public Tranco top list) for three addresses each: /wp-admin/, /admin/ and /api/, following redirects to the end. 216 requests got an answer. 4 of them ended in one of these "other" codes, all from two large platforms: one domain answered 417 Expectation Failed on all three paths, and another answered 400 Bad Request on /admin/. Most sites answered the same missing paths with a 404 (101 of the 216). So the code a server picks for "not here" varies, and Search Console files each under a different row.

That is the part to notice. A server can pick any 4xx code it likes for "no", and some pick unusual ones. So the row doesn't tell you what's wrong. It tells you to go and look at the code.

The words, translated

  • 4xx: the family of codes that mean "the problem is with the request". 404 is the famous one.
  • 400 Bad Request: the server didn't like something about the request itself, such as the address, a cookie or a header.
  • 410 Gone: the page was here and was removed on purpose. Often exactly what you want.
  • 405 Method Not Allowed: the address exists but won't answer that kind of request. Common on form handlers and API addresses.
  • 429 Too Many Requests: the server is asking the visitor to slow down. Google says it treats this one as a server error, not a 4xx, so it doesn't belong in this row.

Step 1: find the exact code

  1. In Search Console, open Pages, scroll to the reasons table and click Blocked due to other 4xx issue. Copy a few example addresses.
  2. Paste one into the search bar at the top (URL Inspection) and click Test live URL, then View tested page and More info. The HTTP response shows the code Google got.
  3. Or ask the server yourself. On a Mac or Linux terminal: 
    curl -sL -o /dev/null -w "%{http_code}\n" https://example.com/the-page/
    On Windows, in PowerShell: 
    (Invoke-WebRequest https://example.com/the-page/ -SkipHttpErrorCheck).StatusCode
    No terminal: paste the address into any free "HTTP status checker" website.

Two warnings from running this. First, keep the -L: without it you only see the first redirect hop (a 301 or 302), not where it ends. Second, if your check says 200 but Google says 4xx, the server may be treating Google differently from you. Pretending to be Googlebot with a changed user agent doesn't prove much either way, because firewalls check Google's real addresses, not the name. Trust the live test in Search Console.

Step 2: decide whether it needs fixing

Ask one question of each address: should a stranger be able to open this page from Google?

  • No (a form handler, a cart action, an API address, a deleted page): the 4xx is correct. Leave it. Remove the address from your sitemap if it's there, and find the link that pointed Google to it if you can.
  • Yes (a product, a post, a service page): something is refusing a real page. Go to step 3.

Step 3: the fix for each code

410 Gone on a page you removed

Nothing to fix. It says the same thing as a 404, more firmly. If the page has a close replacement, a 301 redirect to it is kinder to visitors (see "Page with redirect").

410 on a page you didn't remove

Some redirect and SEO plugins can answer 410 for addresses on a list. Look in the plugin's redirect or "gone" list for the address and delete the entry.

400 Bad Request

Open the address in a private browser window. If it fails there too, look at the address: odd characters, a broken encoding such as % without two characters after it, or a very long query string. Fix the link that produces it. If the page opens fine for you but Google gets 400, look at your firewall or security plugin log for blocked requests at the time of the crawl; a rule that rejects certain headers or query strings can catch Google.

405 Method Not Allowed

The address only accepts form submissions. It isn't a page. Make sure no normal link points to it and it isn't in the sitemap.

A code you don't recognise

Look it up on MDN's list of HTTP status codes, then ask your host which part of the server sends it. Unusual codes like 417 or 451 usually come from one specific piece: a proxy, a firewall or a plugin.

Step 4: tell Google you fixed it

  1. Run Test live URL again on the fixed page. It should say the URL is available to Google.
  2. Click Request indexing for the important ones.
  3. Back on the row, click Validate fix, but only if every address in the row should be public. If some answer 4xx on purpose, validation stops on the first of those and fails.

What I'd skip

  • Don't turn every 4xx into a 200. A missing page that answers 200 becomes a soft 404, which is worse.
  • Don't redirect everything to the home page. Google treats that as a soft 404 too.
  • Don't worry about the count alone. A row full of old form and API addresses is the server doing its job.

The neighbouring rows have their own posts: 403, 404 and 5xx.
