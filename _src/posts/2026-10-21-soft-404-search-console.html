"Soft 404" is a Search Console status. In plain words: Google asked your site for a page, your site answered "here it is, all fine" (status code 200), but what came back looked like an error page, an empty page or a "page not found" message. Google doesn't believe the "all fine" part, so it leaves the page out of its results and lists it here.

On 15 October I asked 193 small business websites from a business directory for a page that can't exist: /this-page-does-not-exist-7q3x. 168 answered 404, page not found. That's correct. 18 answered 200. On 16 October I asked the same 18 for a different made-up page, /no-such-page-k8m2, and all 18 answered 200 again. The other 7 gave a server error or no answer. So about 1 site in 11 told Google that a page it never had exists.

The 18 weren't all doing the same thing:

  • 11 kept the made-up address and served a page. Usually it was the site's normal title and layout. 5 of those 11 are app-style sites: 4 load an empty <div id="root"> and build the page with JavaScript, 1 is built with Next.js.
  • 3 sent the visitor to the home page (or a language home page like /en/). One of those is a WordPress site.
  • 4 sent the visitor to an error page that itself answers 200: /404.php, /error, /500.html and a shop's /password page.

None of these sites look broken to their owners. A visitor who mistypes an address sees something friendly. The only one who notices is Google, and it tells you through this status. Here's how to check your own site and fix each case.

The words, translated

  • Status code is a three-digit number your site sends before every page. People never see it. Google reads it first. 200 means "here's the page". 404 means "no page here". 301 means "it moved, go there".
  • Hard 404 is the honest version: the page doesn't exist and the site says 404. Google drops the address and moves on. Nothing to fix.
  • Soft 404 is when the page says "not found" (or says nothing) but the code says 200. Google's Page indexing help puts it this way: "it returns a user-friendly "not found" message but not a 404 HTTP response code."

Google's guide to HTTP status codes adds the other half: if a page answers 200 but its content "suggests an error", such as "an empty page or an error message, Search Console will show a soft 404 error." So a real page can land here too, if it's nearly empty. That's the second case below.

Step 1: Find out which kind you have

Open Search Console, go to Indexing, then Pages, scroll to "Why pages aren't indexed" and click Soft 404. Open three or four of the listed addresses in a private browser window. Each one will be one of two things:

  1. A page that really is gone, or a "not found" message, or it lands on your home page. Your site should be answering 404. Go to Step 2.
  2. A real page you want in Google, but it's thin: an empty category, a product with no description, a search results page with nothing in it, or a page that looks blank until JavaScript runs. Go to Step 4.

Step 2: Test what your site says for a missing page

Make up an address that can't exist on your site and ask for its status code. On a Mac or Linux, in Terminal:

curl -sL -o /dev/null -w "%{http_code} %{url_effective}\n" https://YOURSITE.COM/no-such-page-test

On Windows, in PowerShell (Windows 10 and 11 include curl.exe):

curl.exe -sL -o NUL -w "%{http_code} %{url_effective}\n" https://YOURSITE.COM/no-such-page-test

The -L matters: it follows redirects, so you see where a visitor ends up, not just the first hop. You want 404 and the same made-up address. If you see 200 and the made-up address, your site serves a page for anything. If you see 200 and your home page, it redirects missing pages home.

No terminal? In Chrome, open the made-up address, press F12 (Cmd+Option+I on a Mac), click the Network tab, reload, and look at the Status column on the first row.

Step 3: Fix the missing-page answer

The goal is the same everywhere: a friendly page for people, with a 404 code for Google. You can keep your nice "not found" design. Only the number changes.

  • WordPress. WordPress answers 404 on its own. When it doesn't, a redirect plugin is usually the cause: some have a setting like "redirect all 404s to the home page". Look in your redirect or SEO plugin's settings and switch it off. Redirect only pages that moved to a real replacement.
  • Shopify. Shopify answers 404 for missing pages: 15 of the 16 Shopify shops in my sample did. The sixteenth sent everything to its /password page, because the shop was still password-protected. Google can't see a locked shop. Remove the password under Online Store, Preferences when you're ready to launch.
  • A custom error page that answers 200 (/404.php, /error). The server sends visitors on to the error page instead of showing it in place. On Apache, ErrorDocument 404 /404.php in .htaccess shows it in place with a 404, as long as you write a path and not a full https:// address (a full address makes Apache redirect). On nginx, error_page 404 /404.html; does the same. If a developer built it, send them this paragraph.
  • Redirecting every missing page to the home page. It feels helpful, but a visitor looking for an old offer lands on a page that doesn't mention it, and Google sees a page that pretends to exist. Redirect an old address only to its real replacement. Let the rest answer 404.
  • App-style sites (React, Vue, anything with an empty <div id="root">). The server sends the same empty shell for every address, with 200, and JavaScript decides later that the page doesn't exist. Google's JavaScript SEO guide gives two fixes: a JavaScript redirect to an address where the server answers 404 (for example /not-found), or adding <meta name="robots" content="noindex"> to the error page with JavaScript. Next.js and similar frameworks have a built-in "not found" function that sends a real 404; use it rather than drawing your own error screen.

Step 4: If it's a real page, give it something to say

When Google flags a page you want indexed, it's telling you the page looks empty. Usual reasons:

  • A category or tag with no products or posts in it. Add some, or remove it from your menu and sitemap so it answers 404.
  • A product page with a name and a price and nothing else. Add a description in your own words.
  • A page whose content only appears after JavaScript runs, or after a slow request. Open the address in URL Inspection, click Test live URL, then View tested page, and look at the screenshot. If Google sees a blank page, so does every assistant that reads your site.
  • Out-of-stock pages that say "no longer available" in large letters. If it's coming back, keep the page and say when. If it's gone for good, let it answer 404, or redirect it to the closest replacement.

Step 5: Tell Google you fixed it

Run Step 2 again. When it shows 404, go back to the Soft 404 row in Search Console and click Validate fix. The pages move to "Not found (404)", which is where a missing page belongs and isn't something to fix. For a real page you improved in Step 4, open it in URL Inspection and click Request indexing.

Validation takes a while. You don't need to wait on it to know you're done: your own test from Step 2 already tells you.

What a soft 404 doesn't mean

  • It isn't a penalty. Google is just leaving those addresses out. Your other pages aren't marked down for it.
  • A few soft 404s on old, gone pages are harmless. Fix the site-wide setting in Step 3 so new ones stop appearing, and the old ones clear on their own.
  • "Not found (404)" in the same report is not an error to fix when the page is really gone. It's the honest answer.

If your home page itself shows up as a soft 404, that's the one to fix today: it usually means Google sees it as empty. My guides on "Crawled – currently not indexed" and "Page with redirect" cover the two statuses people most often confuse with this one.
