If scripts or AI agents drive a Chrome on your machine, it fills up. Every task opens a tab. Most tasks never close it. Headless Chromes started for one screenshot hang instead of exiting. Nothing is broken, so nothing complains, until the machine is out of memory and everything gets slow.

On 13 October one 8 GB laptop I work on was down to almost nothing. Swap was at 19 of 20 GB. One automated Chrome had 47 tabs open. A second headless Chrome had sat unused for 4 days. Three Chromes started with --dump-dom or --screenshot, which should exit within seconds, had been stuck for almost 4 days. A handful of DevTools helper processes had lost their parent and kept running. Cleaning those up brought swap down to 4.7 GB.

That day I set up a cleaner that runs every 10 minutes and closes tabs older than 3 hours. In the 18 days to 30 October it closed 138 tabs. The first day it closed 20, the second 23. The agents were also told that day to close every tab they open. By the last week, the cleaner was closing 1 to 4 a day.

What piles up, and why

  • Tabs in a long-lived browser. An agent opens a page, reads it, finishes its task. Closing the tab is a separate step that nobody asked for. Each open tab keeps its page in memory.
  • One-shot headless Chromes that never exit. chrome --headless --screenshot or --dump-dom should print and quit. A page that never finishes loading, or a script that dies before reading the output, leaves the process running.
  • Orphaned helpers. Tools that talk to Chrome over the DevTools protocol often run as their own process. When the program that started them dies, they keep running with no parent.

See what's open

A Chrome started with --remote-debugging-port=9222 lists its tabs at a local address:

curl -s http://127.0.0.1:9222/json/list

The list includes extension pages, service workers and parts of Chrome's own interface. Only entries with "type": "page" are tabs. Close one by its id:

curl -s http://127.0.0.1:9222/json/close/TAB_ID

To open one, newer versions of Chrome want a PUT: curl -s -X PUT 'http://127.0.0.1:9222/json/new?about:blank'.

Close tabs by age

The DevTools list doesn't say when a tab was opened. So the cleaner has to remember: the first time it sees a tab, it writes down the time, and it closes the tab once that time is old enough. That also means the first run never closes anything, which is what you want from a tool you just installed.

Two rules matter more than the rest:

  • Never close the last tab. When the last tab closes, Chrome quits, and a browser you keep logged in to sites loses its session. If every tab is old, open about:blank first.
  • Only touch the browser you point it at. Your own Chrome doesn't have a debugging port open, so a cleaner that only talks to port 9222 can't touch it.

Here is the whole thing in Python, standard library only. I tested it against Chrome 156:

#!/usr/bin/env python3
"""Close Chrome tabs that have been open longer than MAX_AGE. Run it every 10 minutes."""
import json, os, sys, time, urllib.request

CDP = os.environ.get("CDP", "http://127.0.0.1:9222")
MAX_AGE = float(os.environ.get("MAX_AGE_HOURS", "3")) * 3600
STATE = os.path.expanduser("~/.local/state/tab-ages.json")

def call(path, method="GET"):
    req = urllib.request.Request(CDP + path, method=method)
    with urllib.request.urlopen(req, timeout=5) as r:
        return r.read().decode()

try:
    tabs = [t for t in json.loads(call("/json/list")) if t["type"] == "page"]
except OSError:
    sys.exit(0)  # the browser isn't running: nothing to do

try:
    seen = json.load(open(STATE))
except (OSError, ValueError):
    seen = {}
now = time.time()
seen = {t["id"]: seen.get(t["id"], now) for t in tabs}  # forget closed tabs, start new ones at now

old = [t for t in tabs if now - seen[t["id"]] >= MAX_AGE]
if old and len(old) == len(tabs):
    call("/json/new?about:blank", "PUT")  # never close the last tab: that would quit the browser
for t in old:
    call("/json/close/" + t["id"])
    del seen[t["id"]]
    print(time.strftime("%F %T"), "closed", t["url"][:80])

os.makedirs(os.path.dirname(STATE), exist_ok=True)
json.dump(seen, open(STATE, "w"))

Run it every 10 minutes. On Linux, a cron line is enough:

*/10 * * * * python3 ~/bin/reap_tabs.py >> ~/.local/state/reap_tabs.log 2>&1

On a Mac, a launchd job with StartInterval set to 600 does the same. Keep the log: the day count of closed tabs tells you whether your scripts are getting better at cleaning up after themselves.

Kill the Chromes that never exit

A headless Chrome running a one-shot job for more than a few minutes is stuck. On Linux, ps can show each process's age in seconds:

ps -eo pid,etimes,args | grep -E -- '--(dump-dom|screenshot|print-to-pdf)' | grep -v grep \
  | awk '$2 > 600 {print $1}' | xargs -r kill

macOS's ps has no etimes; use ps -axo pid,etime,command there and read the age column (days-hours:minutes:seconds). Send a plain kill, which asks the process to stop, rather than kill -9.

For orphans, look for the helper's name among processes whose parent is process 1:

ps -eo pid,ppid,etimes,args | awk '$2 == 1 && $3 > 3600' | grep chrome-devtools-mcp

Check what that prints before you add kill to it. Some services run with parent 1 on purpose.

Fix the habit too

A cleaner treats the symptom. The other half is making every script and agent that opens a tab close it when it's done. If your automation uses Puppeteer or Playwright, put page.close() or browser.close() in a finally block, so it runs when the task fails too. If an AI agent drives the browser, write the rule into its instructions: close every tab you open before you finish.

If you want it done for you

The cleaner I run is chrome-reaper, open source under MIT. It does all three jobs in one Go binary: it closes old tabs on the DevTools endpoints you give it, kills one-shot headless Chromes older than 10 minutes, and kills orphans that match a pattern. It has a dry-run mode, and it comes with launchd and systemd examples.

go install github.com/taktekhq/chrome-reaper@latest
chrome-reaper -dry-run -cdp http://127.0.0.1:9222
